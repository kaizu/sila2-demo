# プロジェクト運用ルール

## 目的

この文書は、このプロジェクトを継続的に保守・拡張できるようにするための運用ルールを記録する。
運用方針や決まりごとが変わった場合は、この文書を更新する。

## 文書管理

- プロジェクト文書は `docs/` 配下に Markdown で配置する。
- `docs/RULES.md` を、プロジェクト全体の方針と決まりごとの基準文書とする。
- 実装方針や運用手順が変わった場合は、可能な限り同じ作業の中で `docs/` 配下の関連文書も更新する。
- 新しい文書を追加する場合は、目的が分かるファイル名にし、責務が重複しないようにする。

## 言語方針

- プロジェクトオーナーとのやり取りは日本語で行う。
- `docs/` 配下の文書は、原則として日本語で記録してよい。
- `docs/` 配下以外の成果物は、原則として英語で作成する。
- ソースコード、識別子、ログメッセージ、設定値の説明、ソースコード中のコメントは原則として英語で記述する。
- 外部仕様やライブラリ制約など、英語以外が必要な明確な理由がある場合のみ例外を認める。

## 更新ルール

- 新しいルールを追加する際は、まずこの文書に追記できないかを確認する。
- 一時的なルールは、その背景と終了条件を明記する。
- 実装だけが先行して文書が古くならないように、作業完了時には `docs/` の更新要否も確認する。

## ディレクトリ運用

- `external/` 配下には、直接の開発対象ではないが、実装や調査の参考になる外部ライブラリや関連ソースコードを配置してよい。
- `external/` 配下の内容は参照用として扱い、このプロジェクトの主たる実装対象とは区別する。
- `external/` 配下のコードを変更する場合は、参照元との差分管理や更新意図が明確な場合に限り、通常の開発対象と同じ感覚で安易に編集しない。

## 現在のプロジェクト前提

- このリポジトリは、SiLA2 関連のサーバーパッケージ群と、共有の世界状態サービス `laboratory_model` を含む。
- ローカル実行の基本系は Docker Compose を前提とする。
- `README.md` は入口として簡潔に保ち、継続的に参照する運用知識は `docs/` 配下へ蓄積する。
- `external/` には、参考用の外部実装や依存ライブラリのソースコードが含まれる。
